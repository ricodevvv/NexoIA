# Working on Nexo

Nexo is a Next.js 16 app on React 19, with PostgreSQL through Drizzle, Better
Auth for accounts, and the official Anthropic, OpenAI and MCP SDKs. Package
manager is pnpm 12, node 22.

## The commands

```bash
pnpm install --frozen-lockfile
pnpm dev          # next dev on port 3001
pnpm build        # production build
pnpm typecheck    # next typegen && tsc --noEmit
pnpm lint         # eslint
pnpm test         # vitest run
pnpm test:e2e     # playwright, needs a running app
```

Run `pnpm typecheck` after any change that touches types, and `pnpm test` after
any change that touches logic. Both are fast enough to always run.

## This is not the Next.js you know

This version has breaking changes. Before writing code against an API, read the
matching guide in `node_modules/next/dist/docs/`, resolved from the repo root.
Check for deprecation notices instead of assuming a familiar signature still
works.

## Local setup

```bash
cp .env.example .env
```

The variables that decide whether a feature works at all:

| Variable | Effect when unset |
| --- | --- |
| `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` | No server-wide model; users must bring their own key |
| `STORAGE_DRIVER=s3` with `S3_*` | Attachments are stored as bytea in Postgres |
| `CODE_EXECUTION=1` | `run_python` is off in production, on in development |
| `CODE_SANDBOX_COMMAND` | Pyodide runs in a local Node process instead of a container: no isolation and no package downloads |
| `K8S_API`, `K8S_TOKEN`, `NEXO_WORKSPACES` | No cloud workspaces for the coding agent |
| `STRIPE_SECRET_KEY` | Billing stays off |
| `RESEND_API_KEY` | No verification or password-reset email |

`sandbox/Dockerfile` builds the isolated Python runner, with numpy, pandas,
matplotlib, scipy, sympy and scikit-learn preloaded. It runs on the internal
Docker network `nexo-sandbox`, whose only way out is the egress proxy in
`sandbox/egress.mjs`: HTTP and HTTPS to public addresses, nothing private. Other
packages come in per run through micropip; to make one instant, add it to the
warm list in the Dockerfile and in `WARM_PACKAGES` in `src/lib/code-exec.ts`.

## Where things are

| Path | What lives there |
| --- | --- |
| `src/lib/ai/` | Model providers, tool specs, the system prompt, history |
| `src/lib/ai/providers/` | One adapter per provider family, plus the OpenAI-compatible one |
| `src/lib/ai/builtins.ts` | Tools Nexo answers itself, and their zod schemas |
| `src/lib/widgets.ts` | The `show_widget` schema and its extra cross-field validation |
| `src/components/artifacts/` | The artifact panel and the sandboxed document builder |
| `src/components/code/` | The coding agent UI and the rendering of its tool calls |
| `src/lib/nexocode.ts`, `src/lib/k8s.ts` | The coding agent connection and the workspace pods |
| `drizzle/` | Migrations, generated by `drizzle-kit` from `src/lib/db/schema.ts` |
| `deploy/` | systemd units, Caddyfile, k3s manifests, workspace image |
| `tests/` | Vitest unit tests and Playwright specs |

## Database

```bash
pnpm db:generate   # write a migration after editing the schema
pnpm db:migrate    # apply migrations
```

Never edit a generated migration by hand to make a schema change land. Edit the
schema, generate, then read the generated SQL.

## Conventions

- Comments explain why, not what. Most functions need none.
- Comments, log messages and thrown errors are in Spanish; identifiers are in
  English.
- UI strings the user reads are in Spanish, including the tool descriptions the
  model sees.
- New code uses the strictest type that fits. No `any` to get past the checker.
- Server code that touches auth, billing or file storage needs a route-level or
  unit test.

## Debugging

- `pnpm dev` prints server errors in the terminal; the browser only shows the
  digest.
- Model calls and tool results are in the terminal behind the request that made
  them. Read the actual provider error before changing anything.
- When a tool returns a rejection, read the message: the widget and artifact
  tools report the exact field that failed.
- Sandbox problems are almost always a missing package or a file name that is not
  in `/mnt/data`. Both say so in the output.
